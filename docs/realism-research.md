# 서아의 실사감: 원인과 제작 방향

현재 PINOC 결과는 원본 얼굴과 실사감 기준에 미달한다. 화면 선명도 문제를 고쳤지만 얼굴 형태·피부 디테일은 복원되지 않았다.
**권고는 얼굴과 재질을 직접 수정할 수 있는 MetaHuman 중심 제작으로 전환하는 것이다.** JST 뷰어는 동작 시험과 비교용으로 유지한다.
고해상도 얼굴 참고를 추가한 PINOC 재생성도 1회 시험했으나, 기본 모델을 교체할 만큼 나아졌다고 판단하지 않았다.

## 실제로 확인한 원인

| 가설 | 시험과 결과 | 판단 |
| --- | --- | --- |
| 다른 사진을 잘못 올렸나? | 로컬 원본과 PINOC가 보관한 입력의 SHA-256이 동일 | 입력 파일 착오는 아님 |
| 화면 해상도 때문에만 다른가? | DPR 2, CSS 1000×850에서 기존 실제 버퍼 500×425. 수정 후 2000×1700 | 선명도 문제는 있었지만 얼굴 불일치까지 설명하지 못함 |
| 점 수를 늘리면 얼굴이 돌아오나? | 같은 자산의 high 48,000점과 full 131,072점, 같은 카메라·원형 자세 비교 | 데이터가 약 2.72배여도 원본 얼굴과 세부 피부는 복원되지 않음 |
| 애니메이션이 얼굴을 망가뜨리나? | 동작 없는 원형과 대기 0프레임 비교 | 원형부터 차이가 남음. 동작만의 문제는 아님 |
| 얼굴 참고 사진을 더 넣으면 해결되나? | 전신 원본 + AI로 만든 얼굴 클로즈업, refine=true, 10크레딧 1회 | 실사감 미달 지속. 개선의 충분한 증거 없음 |

원본은 완만하게 웃는 작은 입, 비교적 가는 눈과 자연스러운 볼·턱의 연결을 갖는다. 생성 모델에서는 눈이 더 둥글고 크게 보이고, 입꼬리와 턱선의 인상이 달라진다. 가까이 보면 피부·눈 주변과 머리카락의 디테일도 뭉개진다. 이 판단은 직접 본 렌더에 대한 시각 평가이며, 얼굴 인식 모델이 계산한 유사도 수치가 아니다.

원본 전신 사진은 1024×1536이다. 얼굴이 화면 일부만 차지하므로 사진 전체 해상도를 얼굴 텍스처 해상도로 간주할 수 없다. 새 클로즈업 역시 원본에 없던 미세 정보를 AI가 추정한 자료이지 실제 관측을 추가한 자료가 아니다.

## 바꾼 것과 효과의 한계

- CSS 크기와 DPR을 기준으로 렌더 버퍼를 맞췄다. DPR 상한 2, 최대 약 600만 픽셀로 제한했다. DPR 2 시험에서 버퍼의 가로·세로가 각각 4배, 총 픽셀 수가 16배가 됐다. **얼굴 품질이 16배 좋아졌다는 뜻은 아니다.** 실기기 화면 확대율·브라우저에 따라 기존 버퍼의 차이는 달라질 수 있다.
- 원본 얼굴 확대와 동작을 끈 3D 원형을 나란히 보여준다. 원본을 보정하거나 새 클로즈업으로 몰래 교체하지 않았다. 좌우는 비슷한 머리 크기로 맞췄지만 정밀 카메라 보정은 아니므로 픽셀 단위 얼굴 비율 측정용은 아니다.
- `전신 1장 입력`과 `얼굴 참고 추가 · 실험`을 선택해 비교한다. 기본은 기존 모델이다. 고급 단계라는 이름만으로 실험 모델을 채택하지 않았다.
- 동작 파일 하나가 없어도 모델과 나머지 동작은 남긴다. 모델 전환·실패 후 재시도 시 새 canvas로 WebGL 문맥을 만들도록 고쳤다. 정보 요청 15초, 모델·동작 요청 45초 제한을 넣었다.

이 수정은 **표시·검증·복구 개선**이다. 3D 얼굴 조형과 피부 재질을 다시 제작한 것은 아니다. full 파일도 연구용으로 보존했으며 기본 품질 단계는 high를 유지했다.

## 실사급으로 만들려면

실사감과 원본 유사성은 따로 맞춰야 한다. 피부가 사실적이어도 다른 얼굴이면 실패이고, 정면이 닮아도 회전하거나 움직일 때 무너지면 실패다.

1. **얼굴 기준을 먼저 고정한다.** 전신보다 얼굴을 크게 담은 정면을 기준으로 잡고, 45도·측면을 추가해 눈 간격, 눈꺼풀, 코 깊이, 입꼬리와 턱선을 맞춘다. 가상 인물의 생성된 옆모습은 새로 설계하는 부분이며 정면에서 확인된 사실과 구분한다. 다음 제작의 내부 목표는 얼굴 폭 약 1000px 이상인 참고와 2K 이상 전신이다. 이는 프로젝트의 작업 목표이며 PINOC의 공식 최소 조건이 아니다.
2. **얼굴 형상과 재질을 분리해 제작한다.** 메시의 비율을 먼저 맞춘 뒤 피부 색, 잔주름·모공의 normal, 부분별 roughness와 피부 내부 산란을 조절한다. 눈은 각막·홍채·흰자·젖은 눈꺼풀 경계를, 머리카락은 가닥과 헤어라인을 따로 다룬다. MetaHuman은 피부·눈 재질을 구분하고 이 값들을 조절할 수 있다. [Epic 재질 문서](https://dev.epicgames.com/documentation/metahuman/metahuman-materials-and-textures)
3. **정면 합격 후에 회전과 동작을 붙인다.** 확산광 정면·45도·측면과 방향광 장면에서 확인한다. 다음으로 눈 깜박임·미소·고개 회전, 마지막에 걷기·달리기의 발 접지와 몸무게 이동을 확인한다. 근접 장면을 흐리게 만들거나 멀리 두어 결함을 감추는 방식은 합격으로 인정하지 않는다.

현재 `.vsplat`에는 이 작업에 바로 쓸 편집 가능한 얼굴 메시와 피부 PBR 텍스처 세트가 없다. splat의 조명 효과를 조절할 수 있더라도 그것만으로 없어진 눈꺼풀 형태나 모공을 되살릴 수는 없다. PINOC 캐릭터를 FBX로 이름만 바꾸어 MetaHuman에 넣는 방식도 사용할 수 없다. MetaHuman의 From Mesh는 별도의 FBX/OBJ 메시 입력을 요구한다. [Epic From Mesh](https://dev.epicgames.com/documentation/en-us/metahuman/from-mesh)

## 제작 경로 비교

| 경로 | 필요한 입력과 작업 | 이 프로젝트에서의 판단 |
| --- | --- | --- |
| PINOC 유지 | 사진 1~5장, refine 보정, 결과를 골라 사용 | 가장 빠른 동작 실험. 이번 두 생성 결과로는 얼굴 근접 장면 기준 미달. 같은 조건의 무작정 재생성은 중단 |
| **MetaHuman + 얼굴 조형·재질 수정** | 캐릭터 기준 사진, 프리셋 조형 또는 스캔·조형 메시, 피부·눈·머리카락 작업 | **권고.** 바뀐 얼굴을 직접 고칠 수 있음. 원본 자동 복제를 보장하지 않으며 제작 공정 전환이 필요 |
| Character Creator 5 + Headshot 3 | 얼굴 사진/메시, 형태 수정, 텍스처 재투영·normal 조절 | 사진 기반 편집 대안. 현재 공식 요구 OS가 Windows라 이 Mac에서 바로 쓰는 기본 경로로 고르지 않음 |
| GaussianAvatars | 다중 시점 영상, 얼굴 추적, 개별 학습, CUDA GPU | Gaussian 표현도 실사급에 도달할 수 있다는 반례. 현재의 단일 생성 사진·Apple GPU에 바로 적용할 대체품은 아님 |

PINOC의 사진 수와 refine 비용은 [공식 MCP 안내](https://viggle.ai/pinoc/mcp), Headshot의 편집 기능은 [공식 사진 기반 작업 안내](https://www.reallusion.com/character-creator/headshot/photo-to-3d-head.html), Windows 조건은 [CC5 시스템 요구사항](https://kb.reallusion.com/Product/53240/System-Requirements)에 근거한다. 공급사 기능 설명은 이 캐릭터로 성능을 검증했다는 뜻이 아니다.

MetaHuman Creator는 5.7에서 macOS 지원이 추가됐다. 현 장비는 Apple M4 Max, 메모리 128GiB다. 플랫폼과 메모리 측면에서 시도할 여건이 있지만, 이 작업에서 Unreal을 설치해 성능과 모든 기능을 시험한 것은 아니다. macOS Creator 지원과 모션 캡처 플러그인의 지원 범위는 구분해야 한다. [5.7 공식 발표](https://www.metahuman.com/releases/metahuman-5-7-is-now-available) · [현재 하드웨어·플랫폼 조건](https://dev.epicgames.com/documentation/metahuman/metahuman-hardware-requirements-in-unreal-engine?lang=en-US)

GaussianAvatars는 CVPR 2024 연구로, 다중 시점 영상에서 얼굴 모델과 Gaussian을 함께 최적화한다. 공식 구현은 CUDA GPU와 11GB VRAM을 요구하며 머리 아바타 연구다. 이 캐릭터 전신의 즉석 변환과 같지 않다. 코드의 비상업 라이선스 조건도 별도로 존재한다. ## 반대 가설과 불확실성

- **“Gaussian splat은 원래 실사 표현을 못 한다.”** 위 연구가 반례다. 이번 결과는 표현 방식 전체의 한계가 아니라 이 입력·생성 과정·자산의 품질 문제로 봐야 한다.
- **“점 수만 부족하다.”** 같은 자산의 full에서 개선되지 않았다. 비교한 얼굴 영역 `(370,150)–(630,440)`의 high/full 평균 RGB 절대차는 255단계 중 약 1.06이다. 이는 렌더 간 차이일 뿐 신원 유사도나 실사 점수가 아니다.
- **“참고 사진을 더 넣으면 언제나 좋아진다.”** 이번 1회에서는 충분하지 않았다. 생성의 랜덤성과 추가 사진 효과를 분리할 반복 표본이 없으므로 항상 효과 없다고 일반화하지 않는다.
- **“MetaHuman이면 사진과 똑같아진다.”** 검증하지 않았다. 그것을 추천하는 이유는 성공 보장이 아니라 얼굴 형태·재질을 직접 수정하고 다시 평가할 수 있기 때문이다.

표본은 가상 여성 한 명, 기존 1회와 추가 참고 1회, SDK 0.2.0이다. 공급사 성공 예시에는 선택 편향이 있을 수 있어 결과물의 실사 점수를 그 예시에서 가져오지 않았다. 소프트웨어 업데이트나 더 좋은 입력·학습 방식으로 결론이 바뀔 수 있다. 다른 인물·기기·엔진의 품질 순위, 정확한 제작 시간·비용, 웹으로 내보낸 MetaHuman의 품질은 이번 연구가 답하지 않는다.

## 다음 제작의 합격 기준

- 정면·45도·측면을 원본과 나란히 봤을 때 눈 크기와 간격, 입·턱의 인상이 유지된다. 얼굴 표현이 먼저 합격해야 전신 작업을 확대한다.
- 얼굴이 화면 높이의 절반인 장면에서도 피부·눈꺼풀·헤어라인이 뭉개지지 않고, 방향광이 바뀔 때 눈과 피부가 납득되게 반응한다.
- 고개 회전·미소·눈 깜박임 및 전신 3개 동작에서 얼굴 붕괴와 발 미끄러짐이 눈에 띄지 않는다. 원형과 움직임을 따로 기록한다.

지금의 결과는 이 기준에 합격하지 않았다. 다음 단계는 MetaHuman에서 **얼굴만 먼저 만드는 작은 시제품**이다. 여기까지 통과한 뒤 전신·의상·JST 동작의 재사용 또는 리타기팅을 결정한다. Unreal/MetaHuman 설치와 별도 캐릭터 제작은 이번 연구 산출물에 포함하지 않았다.

## 재현 기록

조사·실험일: 2026-10-21. 논문은 2024 개정판, MetaHuman 5.7 발표는 2025-12-15, CC5 요구사항은 2025-08-27 게시 자료다. 게시일 없는 제품 문서는 조사일에 확인한 내용으로만 취급한다.

```sh
npm ci
npm run dev
# 다른 터미널, 서버 실행 중
node scripts/probe-render.mjs
npm test
npm run build
```

실험 7개는 동일한 CSS 1000×850, DPR 2, FOV 40, 거리 0.95, 시선 높이 1.52에서 실행했다. 원형은 자산의 +X 방향을 -90도 회전해 정면으로 맞췄고, 대기는 원래 +Z 방향의 0프레임이다. 자세에 따라 머리 위치가 달라질 수 있다. `output/research/render-probe.json`에 버퍼 크기·점 수·오류를 보관했다. 모든 브라우저 시험은 격리된 headless Chromium으로 실행했다.

추가 생성 10크레딧, 잔액 50→40. 기존 생성까지 누적 20크레딧. full 다운로드, 무료 동작, 로컬 렌더 시험에는 추가 PINOC 크레딧을 쓰지 않았다.
